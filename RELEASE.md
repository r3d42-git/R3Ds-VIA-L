# Maintainer release procedure

The distribution profile is macOS 13+, with separate Apple Silicon (`arm64`) and Intel (`x64`) ZIP downloads. Build both on macOS using the pinned dependencies (`npm ci`); Electron supports packaging either architecture from the same Mac. Signing is local; CI receives no signing credentials.

1. Run `npm test`, `npm run test:app`, `npm run test:focus` and `npm run test:window`. Runtime tests use isolated profiles and do not authorize real hardware.
2. Set `SIGNING_IDENTITY` to an installed Developer ID Application identity. Store notarization credentials in Keychain using Apple's `notarytool`; use the existing `ToolBoxS` profile by setting `NOTARY_PROFILE=ToolBoxS`. Never put credentials in this repository.
3. Run `node scripts/release.mjs`. This builds `arm64` and then `x64` sequentially from an explicit package allowlist, signs nested code with Hardened Runtime, notarizes each app, requires `Accepted`, staples the app, and only then creates its final ZIP. App folders, notarization ZIPs/results, final ZIPs and checksum files have distinct architecture names. A read-only extracted-artifact check verifies version, bundle ID, signature, stapled ticket, Gatekeeper and architecture, including Electron framework, helpers and nested Mach-O libraries. Each SHA-256 file is written after verification. Use `node scripts/release.mjs --arch=x64` (or `--arch=arm64`) to build only a missing architecture; existing selected outputs cause a stop and must be preserved before retrying.
4. Review and commit the exact source on `main`; push it and wait for its CI `test` check. Keep local notes, profiles and outputs ignored.
5. Run `node scripts/publish-release.mjs --dry-run`, then `node scripts/publish-release.mjs --publish` only when publication is authorized. Both architectures and their checksums must pass verification before any tag or release mutation. Publication creates an annotated version tag, publishes both ZIP/checksum pairs using `RELEASE_NOTES.md`, downloads all four public files afresh, checks downloaded checksum content and local/GitHub digests, and repeats app verification for both ZIPs.

Stop on any failed check. Preserve logs and notarization submission IDs; inspect Apple's result before retrying. Final artifacts are not silently overwritten. The local packaging command `npm run package:mac` intentionally produces a development app without distribution signing/notarization.

Local development packaging accepts `npm run package:mac -- --arch=arm64` or `npm run package:mac -- --arch=x64`; without an architecture it uses the current Node process architecture. Only `arm64` and `x64` are accepted.

Independent verification: `node scripts/verify-release.mjs path/to/VIA-L-VERSION-macOS-x64.zip` (or the `arm64` filename) from the matching source checkout. The expected architecture is inferred from the canonical filename. For a renamed ZIP, provide `--arch=x64` or `--arch=arm64`; a conflicting filename and option is rejected. Intel's Mach-O architecture is `x86_64`.

A verified signature is distinct from a manual launch on a clean Mac and real-device compatibility testing. The four online tools—VIA, Vial, Venom and Wootility—depend on compatible hardware and their respective WebHID behavior. An Intel app smoke test under Rosetta on Apple Silicon does not replace physical Intel Mac tests of connection, reconnect and real keyboard behavior. For 0.2.4, the maintainer confirmed successful hands-on tests with VENOM65HE using Venom and Wooting 60HE+ using Wootility. Before describing hardware tests as missing or excluded, ask the maintainer about their manual test results. Record automated checks and maintainer-confirmed tests accurately; do not infer the overall test status from automation alone.
